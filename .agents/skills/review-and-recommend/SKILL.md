# Review and recommend

1. Review the relevant data, issues, code, and git history.
2. Present real options (numbered) with associated effort (`Easy` · `Medium` · `Hard`).
3. Make a **recommendation**.
4. Call out the **right fix**. If it differs from the recommendation, explain why.
5. Stop and wait for a choice — do not implement yet.
